什么是 MCP

1一句话和分层
一句话

FC 管表达，MCP 管接入；一个宿主连多个服务端

层是什么我的项目
宿主正在用的应用我的平台、IDE
客户端宿主里连服务端的连接器，一个服务端一个每个连接一个 SDK client
服务端提供工具和数据的一方文件系统、数据库、内部接口
协议发现与调用的报文JSON-RPC 2.0，Streamable HTTP
USB 比方，再往下一层

插上以后主机先读设备描述符，知道这个设备有什么能力，对应 tools/list 返回的 schema；之后每次操作走标准报文，对应 JSON-RPC；线本身不决定能不能用，驱动和权限才决定，对应到 MCP 就是白名单、只读、scope 仍然是宿主自己的事。

所以 MCP 只解决能不能接、怎么接，不解决该不该让它做。

3完整回答

MCP 是 Anthropic 提的标准，用 JSON-RPC 让宿主发现和调用外部工具。分四层：宿主是应用，客户端是宿主里连服务端的连接器，服务端提供工具和数据，协议规定报文。

它和 Function Calling 不冲突。模型最后输出的还是 tool_call，MCP 只是把这个工具从哪来、怎么调通标准化了。没有 MCP，N 个应用接 M 个工具要写 N×M 套适配；有了 MCP，工具方各写一个服务端，应用方各写一个客户端，变成 N+M。

一次调用是：初始化，拉工具列表拿 schema，绑成本地工具，模型调用时把参数原样转发，结果回填。

我项目只做客户端，用 Streamable HTTP，token 从环境变量读，配置里不存凭据。拉回来的工具单连接上限 100 个，只有声明为只读的才能执行。工具名不用原名，用连接加摘要生成，schema 一变名字就变，固定版本的 Run 不会悄悄调到改过的工具契约。

4我的实现
传输Streamable HTTP；地址只允许 http/https，不能带凭据，不跟随重定向
鉴权配置只存环境变量名，运行时读出来加 Authorization: Bearer
发现分页拉，单连接上限 100 个工具，游标重复直接报错
绑定本地名 mcp_ 加 20 位摘要，endpoint、凭据变量名、工具 schema 都参与
执行连接启用、工具还在目录、readOnlyHint 为 true，三条都过才调
超时连接 10 秒、请求 20 秒、初始化 10 秒
5可能被追问
  • MCP 和 Function Calling 冲突吗？→ 不冲突。MCP 的工具最后还是要变成模型的 tool schema，模型输出的还是 tool_call。
  • 为什么需要 MCP？→ 适配次数从 N×M 降到 N+M；工具方维护服务端，应用方只写一次客户端。
  • MCP 只有工具吗？→ 规范里还有 resources 可读数据和 prompts 模板，我只用了 tools。
  • 传输方式？→ 本地 stdio，远程 Streamable HTTP；我只做后者，老的 HTTP+SSE 没接。
  • 你怎么保证安全？→ 地址不带凭据，token 走环境变量，只执行只读工具，再加连接启停、白名单、参数校验和调用预算。
  • 工具重名怎么办？→ 不暴露远程原名，用连接加摘要生成本地名。
  • 服务端改了工具怎么办？→ 重新发现；名字带 schema 摘要，旧 Run 调不到新契约。
  • 为什么没写服务端？→ 需求是消费外部工具；写服务端是另一件事，等于把现有工具网关对外暴露。
缺口

只做客户端；只接 Streamable HTTP；只执行只读工具；没接 resources 和 prompts；鉴权只有 Bearer，没有 OAuth。
