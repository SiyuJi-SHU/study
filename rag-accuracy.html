1

RAG 怎么保证准确

1一句话和流程
一句话

不可能 100%，只能把出错概率压低；三层是架构、防护、兜底

方案什么规模用代价
架构层混合检索、切片、元数据；生成严格依据上下文、temperature 0、输出 JSON我做了双路 RRF、Rerank、submit_answer 结构化输出
防护层第二个 LLM 复核幻觉、界面溯源、关键词库校验我做了程序回填引用、版本和数字校验；复核没做
兜底层语义分数阈值拒答、人工复核、全链路日志我做了 rerankScore 0.15 阈值、无证据就说明、run_events 留痕
2完整回答

这题开口先给结论：不可能保证 100%。模型是概率的，检索有召回上限，文档本身也可能错，调参数解决不了。

能做的是工程和业务三层。

架构层管住输入。检索上做混合，稠密加稀疏，切片保上下文完整，元数据打标。生成上要求严格依据上下文，temperature 设 0，甚至不让模型自由写文案，直接输出结构化 JSON，内容来自原文。

防护层管住输出。可以再加一个模型做幻觉复核，比对回答和原文；界面上做溯源，让用户点开看原文；医疗法务这类术语要求严的行业，可以建关键词库，命中就核对描述和解释。

兜底层管住最坏情况。检索分数设阈值，低于阈值直接拒答，不硬编；高风险场景加人工复核；全链路日志，出问题能追到是哪一步。

我项目里：架构层是双路召回加 RRF 加 Rerank，生成走 submit_answer 结构化输出，temperature 0；防护层是引用由程序从原文回填，再校验 Evidence ID、版本、句子编号和数字；兜底层是 rerankScore 低于 0.15 的文档直接过滤，没证据就说明本次没找到，全过程写 run_events。第二个模型复核和人工复核没做，这是缺口。

3我项目里的代码
chunks.stream().filter(c -> c.rerankScore() != null && c.rerankScore() >= 0.15)
4可能被追问
  • 为什么 temperature 0 也不能保证？→ 概率模型加检索上限，加文档本身可能错，参数只降低随机性。
  • 第二个模型复核值不值？→ 成本和延迟翻倍，只在高风险领域值得，不能全站默认开。
  • 怎么拒答？→ rerank 分数阈值加无证据说明，不能既没证据又硬答。
  • 引用怎么防串版本？→ Evidence ID 用 documentId、version、start、end 做哈希，版本变了 ID 就变。
缺口

没做第二模型复核、关键词库和人工复核；只有程序侧校验。
