1

A2A 是什么

1一句话和五个对象
一句话

Agent Card 发现 → Task 状态机 → Message / Artifact → 与 MCP 分工

对象是什么一句话
Agent Card能力名片，放在约定的 well-known 地址告诉别人我会什么、地址、怎么认证
Task一次委派，有自己的状态机不是调用，是张有生命周期的工单
Message双方说的话parts 可以是文本、文件、结构化数据
Artifact产出物任务交付的结果
状态机生命周期submitted / working / input-required / completed…
2一个例子
跨公司委派
拉 Agent Card→ 建 Task→ working→ input-required→ completed + Artifact
A 公司的报销 Agent 把单子送去 B 公司的财务 Agent：先拉 Agent Card，知道它有合规审查这个 skill 和 endpoint；再建 Task，Message 里带报销单；对方 submitted 再 working，缺发票时 input-required 反过来追问；补一条 Message 后 completed，返回 Artifact 合规结论。A 不知道 B 内部实现，也不共享数据库。
3完整回答

A2A 是 Agent2Agent，Google 牵头提的，让不同进程、不同厂商的 Agent 互相发现、委派任务、交换结果。它和 MCP 分工不同：MCP 是 Agent 调工具，A2A 是 Agent 找 Agent。

一次协作分四步：先拉 Agent Card 做发现，拿 skills、endpoint 和认证方式；再建 Task，Message 带文本、文件或结构化数据；执行时状态走 submitted、working，需要补充信息就进 input-required，回头追问；完成后返回 Artifact。Task 是有状态机的，可以长时间跑、可以中断、可以取消，更适合跨组织的长任务。

我项目没实现 A2A。我的场景是一个进程内的编排，不涉及跨 Agent 委派；要接的话，成本在身份、信任和任务幂等，不在协议本身。

4可能被追问
  • A2A 和 MCP 什么区别？→ MCP 是 Agent 调工具，一问一答；A2A 是 Agent 找 Agent，有 Task 状态机，能长跑、能追问、能取消。
  • A2A 靠什么发现对方？→ Agent Card，放在约定的 well-known 地址，写清 skills、endpoint 和认证方式。
  • 传输和推送？→ JSON-RPC over HTTPS；任务更新可以流式推，也可以用 webhook 回调。
  • 为什么要有状态机？→ 跨组织任务耗时长，要能表达“等我补材料”和“已完成”，不然只能靠超时。
  • 你项目为什么没做？→ 单进程编排，没有跨 Agent 委派；要接的成本在身份、信任和幂等。
  • 多 Agent 一定用 A2A 吗？→ 不一定，同进程内用线程或图编排更便宜；跨组织、跨厂商才需要协议。
  • A2A 和 MCP 会一起用吗？→ 会，Agent 之间用 A2A 委派，各自再用 MCP 调自己的工具。
缺口

没实现，只做方案对照；Agent Card 的认证细节和 push 回调的重试语义没深究。
