2完整回答

面试官好，我叫纪思羽，本科和硕士都就读于上海大学，目前是电子信息专业的 2027 届硕士，研究方向是工业视觉测量，应聘方向是 AI 应用开发工程师。

在复星数智化与 AI 条线实习期间，我参与了基于 Dify 的村医助手功能迭代和 UAT 验收，也做过多家云平台模型 API 的兼容性、并发和时延评测，形成阶段性的选型建议。在参与 DeepParser 企业级 Agent 平台接入与评测的过程中，我进一步接触到不同业务对知识检索、上下文完整性和答案依据的要求。

结合这些实践，我全栈开发了 Totoro Nexus，这是一个基于 Java、Spring Boot 和 Spring AI Alibaba 的可配置 Agent 与知识库评测平台，覆盖资料入库、Agent 配置、对话和评测，技术上主要围绕 Agent 执行、RAG 和效果评测展开。

项目里，我重点做了两个设计。第一是把配置版本与运行记录关联起来，将模型、知识范围、工具权限和执行模式等配置版本化存在 PGSQL 里面，让历史请求能够追溯到当时的配置、工具调用和引用证据，为排查问题提供依据。第二是把检索定位和证据阅读分开：先通过向量与关键词混合检索定位相关小块，对通过筛选的命中自动补充周围的原文上下文；仍然不足时，再按需续读，并由程序回填和校验引用，减少单个片段缺少必要前后文的问题。

为了判断这些设计的实际效果，我还做了分层评测，结合召回指标、证据覆盖和回答检查，帮助区分问题发生在召回、重排、证据补充还是生成环节，而不是只看最终答案对不对。

科研方面，我有一篇 IEEE TIM 第一作者论文在审，研究工业视觉边界检测与几何测量，涉及自建数据集和参数高效适配。

当然，关于 Agent 的配置不存在一个具体的标答，我全栈构建的 Agent 里面很多设计仅仅基于我的一些考量：Agent 上下文的配置、Agent 的意图路由、RAG 的链路，都是基于我具体的项目场景做的选型。如果让我重做一次，我确实能发现不少可以改进的点。我希望能够加入贵司，把自己学习的知识落到具体的业务中。

3可能被追问
  • 为什么从工业视觉测量转到 AI 应用开发？→ 研究方向本质是「把通用模型适配到专用场景」；我更想做把模型接进业务这一层——模型能力有边界，工程能补，评测能证明补住了。三句，20 秒内。
  • Totoro 两个设计分别解决什么？→ 一是配置版本与运行记录绑定，历史请求能追溯到当时的模型、知识范围、工具权限、执行模式和引用证据；二是检索定位与证据阅读分开，命中后补上下文、不足再续读，引用由程序回填校验。
  • 分层评测怎么定位到环节？→ 召回指标看召回、证据覆盖看重排与补充、回答检查看生成；三者分开看，才能说清问题卡在哪一环。
  • DeepParser 具体做了什么？→ 企业级 Agent 平台的接入与评测，让我接触到不同业务对知识检索、上下文完整性和答案依据的不同要求。
  • 项目是你一个人做的吗？→ 方案设计、技术选型和评测体系由我主导，开发我参与了主体实现；口述里的「全栈开发」和简历口径要保持一致。
