上下文怎么管理

1一句话和流程
一句话

五块预算，四段压缩；压缩只影响模型，不删数据库

阶段什么时候做什么
T1全程工具调用只留结果，过程裁掉
T2到 30%消息分级，低优先级搬去存档，可回拉
T3到 60%按天做局部摘要
T4到 90%全局摘要 + 外部档案
补充

2026 多三件事：划逐字保留区（System、工具 schema、任务目标、最近 5 到 7 轮），工具结果留占位符，摘要后回测关键事实。

System 和工具 schema 字节不变，可以命中前缀缓存。

2完整回答

上下文管理就两个问题：给模型看多少，历史放哪。

给模型看的分子五块：System 固定不动；工具结果只留结论；历史分级处理；当前提问不动；输出留余量。

压缩分四段。T1 全程做：工具调用只留返回值，中间查了哪几篇、怎么想的全去掉。T2 到30%：低优先级消息搬去存档，需要时再拉回来。T3 到60%：按天做局部摘要。T4 到90%：全局摘要，再加一份外部档案，存稳定偏好和长期事实。

如果都压缩了，用户还怎么看历史？答案是两套数据。用户看到的历史从数据库完整读，压缩只影响这一轮送给模型的上下文。

我项目里的对话历史在 PostgreSQL，三张表管三件事：agent_sessions 存会话本身和绑定的 Agent 版本；agent_runs 一次问答一行，input_json 是问题，result_json 是答案和引用；run_events 存过程事件，比如检索、工具调用、阶段变化。本地磁盘只放原始文档，也就是知识库那些 md 文件，按版本存不覆盖；Milvus 和 Lucene 只是可重建的索引，不是事实源。

上下文这边是滑窗加字符预算，四个数各有用途：Router 只看历史回答的 1600 字，因为判断意图不需要细节；主模型看到的历史回答每条截到 8000 字；追问时恢复上一轮被引用的证据，上限 24000 字；本轮所有证据的总预算是 60000 字，超了返回 budget_exhausted，让模型用已有证据作答。自动摘要和外部档案还没做。

3我项目里的代码
history = history.filter(h -> h.resultJson() != null);  // 只留出结果的
int first = Math.max(0, history.size() - 4);            // 最近 4 条运行
if (anchor >= 0 && anchor < first) selected.add(history.get(anchor));  // 诊断单独锚住
clip(answer, 1600);       // Router 只拿到 1600 字
clip(text, 8000);         // 历史回答进模型
historyForModel(history, 24000);  // 追问恢复上一轮
// 本轮证据预算 60000，超了返回 budget_exhausted
4可能被追问
  • 输出也占上下文吗？→ 占。窗口是输入加输出共享，要预留 max_tokens；而且本轮输出下一轮会变成输入。
  • 你的滑窗多大？→ 最近 4 条有结果的运行，外加最近一次诊断单独锚住；每条答案截 8000 字，Router 只看 1600 字。
  • 压缩最怕丢什么？→ 目标和约束。goal drift 一旦发生，模型还在做事，方向已经偏了。
  • 工具结果能直接删吗？→ 不能，要留占位符，让模型知道这里调用过。
  • 摘要丢信息怎么办？→ 证据保持原文，关键事实写进外部档案，摘要后用固定问题回测。
  • 30、60、90 是标准吗？→ 不是，是经验值。业内常用 70 到 80% 或任务边界触发，还要留输出余量。
缺口

只有滑窗加字符预算，摘要、保留区、外部档案都没做。
