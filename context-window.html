1

扩窗与引用绑定

1一句话和流程
一句话

chunk 只定位 → 回原文扩窗 → 三个数字 → Evidence ID → 可追溯不等于正确

2完整回答

Chunk 只适合定位，块边界可能切断一句话、一张表或一个步骤。所以命中后按记录里的 documentId、version、offset 回不可变原文，扩成连续窗口；多个窗口重叠时程序做区间并集，避免同一段原文重复出现。

三个数字要记清：1200 是 Chunk 最大字符数，200 是超长段落拆分时的 overlap，已包含在 1200 内；6000 是命中后单个阅读窗口的上限，不是前后各 6000。

引用不串版本靠两层：Evidence ID 由 documentId、version、start、end 哈希生成，版本变了 ID 就变；模型只提交 Evidence ID 和窗口内句子编号，quote 由程序回原文取，再校验引用存在、版本一致、编号不越界。

Evidence 不是新的一层，就是这组元数据加一个程序窗口。ID 只是短句柄，真正可溯源的是背后的版本和 offset。成本就是字符串切片和一次哈希，相比模型调用可以忽略。

所以引用保证的是可追溯，不保证答案一定对。

3可能被追问
  • 1200、200、6000 分别是什么？→ 1200 单块上限，200 拆分重叠，6000 单窗口阅读上限。
  • 引用怎么不张冠李戴？→ 版本和 offset 取自不可变原文，ID 按版本哈希，版本变 ID 变。
  • 引用能保证答案对吗？→ 不能，只保证可追溯到原文那一段。
缺口

"可追溯 ≠ 正确"这句要主动说，不能等面试官挑。
