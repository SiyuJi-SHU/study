SSE 与断线续接

1一句话和链路
一句话

SSE 是一个不结束的 HTTP 响应；我项目里是先落库，再按游标把事件搬到浏览器。

一条流的走法
订阅 stream?after=N→ 查 sequence 更大→ 每 300ms 推增量→ 终态发 done→ 断线带游标补
2数据长什么样
实际字节是这样：data: 一行写完，换行，再一个空行，才算一条事件结束。
event: token
id: 12
data: {"delta": "今天"}


event: token
id: 13
data: {"delta": "天气"}
写成一行就是 data: {"delta": "今天"}\n\n，空行就是两个 \n。少了这个空行，前端要么只收到一条，要么直接解析不出来。
我项目里事件类型不是 token，是阶段和结果：
event: stage
id: 7
data: {"phase": "retrieval_plan"}


event: answer_text
id: 12
data: {"text": "报销需在 30 天内提交"}


event: done
data: {}
三条规则

- 空行是边界：两个 \n 才算一条结束，这是最容易写错的地方。

- data: 必须单行，JSON 要压平，换行会被切成多条。

- id: 就是 sequence，断线时浏览器会把它放进 Last-Event-ID。

3完整回答

SSE 最常见的表现就是打字机效果：回答一个字一个字往外冒。它底下的机制是一个不结束的 HTTP 响应——响应头 text/event-stream，服务端保持连接、一条条写事件，客户端边收边处理。

我项目里不是把模型吐的字直接推给浏览器。Run 在线程池里跑，执行中的阶段事件先写进 run_events，主键是 run_id 加 sequence；浏览器订阅 /runs/{id}/stream?after=0，服务端每 300 毫秒查一次比游标大的事件，带 id 和事件类型推过去；Run 到终态、并且这一批读完，再发 done 关闭连接。

断线之后，前端重连带 after，浏览器也会把最后收到的 id 放进 Last-Event-ID，服务端取较大的那个，只补没收到的事件。事件在库里，所以刷新、换实例都能补；模型不重跑，不会重复烧 token，也不会两次答案不一样。

有个细节我特意处理了：先读 Run 状态，再读事件。反过来，正好在两次读之间终态提交，最后一批事件就漏了。

4断线之后
问题怎么接注意
重复客户端按 sequence 去重服务端不做 exactly-once
缺段after 和 Last-Event-ID 取较大值只查 sequence 更大的事件
从头重生成先落库再推事件只在内存，就只能重来
什么时候收尾一批不满 200 且已终态，发 done先读状态再读事件，防漏最后一批
5可能被追问
  • 为什么不用 WebSocket？→ 这条链路只有服务端到客户端的单向流；SSE 基于 HTTP，鉴权和限流能沿用网关，浏览器自带重连。要双向才值得上 WebSocket。
  • 为什么 300ms 轮询，不让执行线程直接推？→ 执行线程只管写库，SSE 线程只管读库，两边解耦；代价是最多 300ms 延迟，换来进程重启和换实例都能补。
  • 断线会漏事件吗？→ 游标只增不减；先读 Run 状态再读事件，避免终态提交那一瞬间漏掉最后一批。
  • 会重复吗？→ 会，客户端按 sequence 幂等去重；服务端不追求 exactly-once。
  • 多实例怎么办？→ 事件在共享库里，任何实例都能补；emitter 是进程内的，重连到别的实例也能续。
  • 事件表会一直涨吗？→ 会，要按 Run 归档或设保留期；我现在没做 TTL。
缺口

事件没做 TTL 或归档；反向代理的响应缓冲没显式关闭；HTTP/1.1 同域连接数有限，多标签页没做连接合并。
