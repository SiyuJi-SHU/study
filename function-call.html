什么是 Function Call

1一句话和流程
一句话

Tools 是能力，FC 是调用方式；模型只表达，后端才执行；工具描述占上下文

模型侧
用户提问：帮我查下今天北京的天气
↓
LLM 输出 function(weather, {city: 北京, date: 今天})
↓
LLM 继续下一步 or 直接作答
后端侧
网关校验：白名单 / Schema / scope / 预算
↓
工具 API 真正执行
↓
Observation 回填结果
工具多了怎么办
100 个工具→100 份描述进上下文→挤占预算 / 幻觉 / 选错→按意图路由到 Sub Agent→每个只挂自己的工具
打个比方：一排办事窗口
tool一个办事窗口
description窗口上贴的说明牌
parameters要填的申请表
tool_calls填好但还没递进去的单子
Observation窗口递出来的结果
tool_call_id取件号
2完整回答

Tools 和 Function Call 不是一回事。Tools 是能力本身，Function Call 是模型调用这个能力的方式。

把它想成一排办事窗口：每个窗口只能办一件事，窗口上贴着说明牌，你要填一张申请表。模型做的只是把申请表填好，它不进窗口办事。

用户说“查一下今天北京的天气”，模型不执行任何东西，只输出一段结构化参数：function(name=weather, arguments={city: 北京, date: 今天})。真正的调用在后端，结果作为 Observation 回填，模型再决定下一步。

这里每个 tool 的定义里都有 name、description 和参数 schema，这些会作为请求里独立的 tools 字段发出去，和 system、user 抢同一个上下文窗口，所以描述本身就在吃预算。工具少没事；到一百个，就是一百份描述在吃预算，会幻觉、会选错。所以要在外面再加一层：按意图路由到子 Agent，每个只挂自己的工具；或者对工具描述做检索、按需加载。

一句话：FC 解决模型怎么表达调用，不解决工具怎么组织。

我项目里三种模式用的是同一批工具，最后都过同一个网关：白名单、Schema、scope、预算，结果统一回填。

3我项目里的代码

这三段是原生 Function Calling 的形状，对应 ReAct。

① 发给模型的工具定义（AgentToolRegistry 的 knowledge.search，转成 OpenAI schema）：

{
  "type": "function",
  "function": {
    "name": "search_knowledge",
    "description": "按问题找相关文档片段；支持向量、全文 BM25 或混合检索。省略 mode 时使用知识库配置。命中后按需读取原文。",
    "parameters": {
      "type": "object",
      "properties": {
        "query": { "type": "string", "description": "保留专有词、错误码和否定条件" },
        "mode":  { "type": "string", "enum": ["semantic", "keyword", "hybrid"] }
      },
      "required": ["query"],
      "additionalProperties": false
    }
  }
}

② 模型这一轮只输出调用意图，不执行：

{
  "tool_calls": [{
    "id": "call_7f3a",
    "type": "function",
    "function": {
      "name": "search_knowledge",
      "arguments": "{\"query\": \"报销流程\", \"mode\": \"hybrid\"}"
    }
  }]
}

③ 后端执行完，回填成一条 tool 消息：

{
  "role": "tool",
  "tool_call_id": "call_7f3a",
  "name": "search_knowledge",
  "content": "{\"status\": \"ok\", \"mode\": \"hybrid\", \"documents\": [{\"id\": \"D-3f2a\", \"documentId\": \"doc-12\", \"version\": \"v3\", \"start\": 1200, \"end\": 2400}]}"
}
4可能被追问
  • 模型真的在执行工具吗？→ 不执行。模型只出调用意图，执行和副作用都在后端，模型没有权限。
  • 一百个工具除了拆子 Agent 还有什么办法？→ 对工具描述做检索、按命名空间分组、按需加载、按角色裁剪可见工具。
  • FC 和 MCP 什么关系？→ 不同层。FC 是模型怎么表达，MCP 是工具怎么接进来；MCP Server 的工具最终会被转成 FC 的 schema 交给模型。
  • Plan 模式是交给另一个子 Agent 执行吗？→ 不是。模型只输出 action、tool、arguments，由同一个 Java 执行循环调网关；三种模式是同一个执行器接口的三个实现，不是三个 Agent。
