一次请求的完整链路

1一句话和流程
一句话

鉴权 → 建 Run → 路由 → 工具网关 → 双路召回 → 扩窗 → 回填 → 落库推送

2完整回答

用户发送后，前端把 Agent、Session、问题和附件提交给后端。接口层先做登录权限校验，确认 Session 和应用归当前用户；新 Session 就把当时的 Agent 版本固定下来，后面改配置不影响这一轮。

然后建一个 queued 的 Run，同一 Session 同时只允许一个 Run。Runtime 设定这轮的总超时、工具调用次数和证据预算。

Router 先判意图：知识问题、闲聊、追问还是澄清。知识问题进入 Agent 版本指定的执行模式，模型决定调哪个工具，但工具要过 Java 网关的白名单、参数和 scope 校验后才真正执行。

检索走两路召回、融合、精排，命中后回原文扩窗，证据带上 Evidence ID。模型交草稿，程序回填引用并校验数字和引用是否存在。

最后答案、证据、用量写进数据库，通过 SSE 把状态和结果推给前端。中间有失败就标记失败或降级，不伪装成功。

3可能被追问
  • 新 Session 为什么固定 Agent 版本？→ 保证这一轮以后改配置不影响它，结果可复现。
  • 工具真是模型在执行吗？→ 不是，模型只出意图，网关校验后才执行。
  • 失败怎么处理？→ 标记失败或降级，绝不伪装成功。
缺口

链路要顺口背出，别在"回填 vs 生成"的措辞上卡壳；可复现、可归因是这条链的两条主线。
