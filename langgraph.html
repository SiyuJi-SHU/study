1

LangGraph 与我的对照

1一句话和流程
一句话

图表达控制流 → checkpoint 存状态 → 三要素 → 我的三句对照

2完整回答

LangGraph 是面向长运行、有状态 Agent 的低层编排框架，把流程表达成图，提供 checkpoint、durable execution 和 human-in-the-loop。它比 LangChain 的高层 Agent API 更关注控制流和运行状态；LangChain 偏组件组合，LangGraph 偏图执行和状态恢复。

StateGraph 三要素：State 是所有节点读写的共享状态，Node 是执行单元，Edge 是转移。普通边固定，Conditional Edge 按状态或模型输出选下一节点。

Checkpoint 在每个 super-step 存状态快照，支持恢复、时间旅行和人工审批；Interrupt 在节点内暂停，恢复时该节点从头重跑，所以副作用要幂等。

和我的项目对照三句：它用图管控制流，我用 Java 类固定三种模式；它用 Checkpoint 存状态，我用 Session、Run、run_events 落库；它适合流程常变和中断恢复，我流程稳定，所以没引入。权限预算超时在 Runtime 层，LangGraph 不替你做，迁移代价是状态、幂等和恢复语义要重新定义。

3可能被追问
  • StateGraph 三要素？→ State、Node、Edge。
  • 为什么不引入 LangGraph？→ 流程固定三类，状态已落库，没时间旅行需求。
  • Checkpoint 和 Interrupt 区别？→ Checkpoint 存快照可恢复，Interrupt 在节点内暂停、恢复时重跑该节点。
