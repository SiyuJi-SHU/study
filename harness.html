Harness 与 Runtime

1一句话和六层
一句话

Harness 是驱动模型干活的脚手架，Runtime 是承载和治理一次运行的底座；模型只负责说话，其余都是工程。

3完整回答

Harness 和 Runtime 都是模型之外的控制层，但站位不一样。

Harness 是驱动模型干活的脚手架：喂任务、给工具、跑循环、收结果，它决定模型看到什么、能调什么、什么时候停。Runtime 是承载和治理一次运行的底座：会话和版本、Run 的状态、并发、超时、事件、持久化。

我项目里两者都能指到代码。Runtime 在 AgentRuntime 和 AgentRunStore——Session 创建时固定版本，一个会话同时只有一个活动 Run，事件按 (run_id, sequence) 追加，SSE 推给前端，超时由 ModelDeadline 中断。Harness 有两处：三个执行器，ReAct 的 tool loop、Plan 的三阶段、Workflow 的固定流程；还有评测 Runner，喂 case、跑完、收集，算 hit@k、targetRecall、MRR，再按 candidate_miss、rerank_loss、evidence_gap 归因。

这套架子一般分六层：接入、上下文、循环、检索、模型、工具。控制流是一代代演进过来的：最早的问答只靠模型自己；后来加检索，先找证据再回答；再加意图识别和路由；最后是多步循环或图编排，可以中断、可以恢复。

我项目在第三代加固定工作流。三种执行模式写死，好处是可预测、好评测；代价是不支持任意拓扑，也没有自动摘要和跨会话记忆。

一句话：Harness 决定模型怎么干活，Runtime 决定这次运行怎么被管住。

4可能被追问
  • Runtime 是新概念吗？→ 不是，JVM、容器 runtime 早就有；新的是 Agent Runtime 这个叫法，各家定义还不统一。
  • 一次请求链路里哪段是 Runtime？→ Session 固定版本、Run 状态机、事件和持久化那段是 Runtime；执行器怎么驱动模型、评测怎么跑，是 Harness。
  • 两者有重叠吗？→ 有：预算和超时既在脚手架里消费，也在治理里限额；但代码上是两层。
  • 你项目的 Harness 在哪？→ 三个执行器加评测 Runner，不是抽象名词。
  • Harness 和框架有什么区别？→ 框架提供积木，Harness 是把积木装成能跑的系统，含预算、恢复、降级。
  • 为什么不做通用图编排？→ 流程是固定的三种，图编排带来灵活性，也带来不可预测和调试成本。
  • Claude Code 的压缩你能用吗？→ 思路能借，水位是经验值，要落到我的三档预算上，不能照抄百分比。
  • 子 Agent 一定要有吗？→ 只在任务可并行、方向能拆开时才值得；否则就是多一层调度。
缺口

没有通用图编排、没有自动摘要、没有跨会话记忆；评测 Harness 只在离线跑，没接 CI；工具都在本进程执行，没有沙箱隔离。

边界

这两个词各家定义不统一，我给的是工程口径，不是标准定义。
