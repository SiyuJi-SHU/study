2完整回答

Harness 这个词听着玄，其实就是模型之外的那一整套架子。模型只负责生成文字，它不会自己记上下文、不会自己调工具、不会自己重试、也不会自己恢复中断。

这套架子一般分六层。接入层管会话和流式输出；上下文层管拼装和压缩；循环层管推理、调工具、看结果、再推理；检索层负责找证据；模型层管选模型、参数、超时和降级；工具层管定义、鉴权、执行和结果回填。

有代表性的样板是 Claude Code：上下文用到一定比例就开始压缩，复杂任务拆成子 Agent，跨会话的信息放到外部记忆。它的水位是经验值，不是行业标准。

这类系统的控制流也是一代代演进过来的：最早的问答只靠模型自己；后来加检索，变成先找证据再回答；再后来加意图识别和路由，先判断做什么再分给对应流程；最后是多步循环和图编排，可以中断、可以恢复。

我项目在第三代加固定工作流。三种执行模式是写死的，好处是可预测、好评测；代价是不支持任意拓扑，也没做自动摘要和跨会话记忆。

3可能被追问
  • Harness 和框架有什么区别？→ 框架提供积木，Harness 是把积木装成能跑的系统，含预算、恢复、降级。
  • 为什么不做通用图编排？→ 我的流程是固定的三种，图编排带来灵活性，也带来不可预测和调试成本。
  • Claude Code 的压缩你能用吗？→ 思路能借，但要落在我的四档预算上，不能照抄百分比。
  • 子 Agent 一定要有吗？→ 只在任务可并行、方向能拆开时才值得；否则就是多一层调度。
缺口

没有通用图编排、没有自动摘要、没有跨会话记忆。
