1

幻觉与提示注入

1一句话和流程
一句话

策略 → 执行 → 引用 → 权限 → 兜底

2完整回答

这题按一条链答：先限制它能不能用通识，再规定它拿什么答，然后校验引用，最后用评测兜底。

第一层策略。Agent 有 allowGeneralKnowledge 开关，代码里还会做第二次判断：只有开关打开、不是 Workflow、不是事故诊断、basis 是 GENERAL 或 MIXED，才允许通识；否则一律按必须取证处理，Router 误判也过不了。

第二层执行。知识问题先取证；没证据就说明本次没找到，或让用户补充；System 里明确写本轮允不允许通识，不让模型自由发挥。

第三层引用。模型只提交 Evidence ID 和句子编号，原文由程序从不可变原文取，再校验引用存在、版本一致、数字对得上；校验不过就修复或降级。

第四层权限。检索内容、附件、工具返回都当不可信数据，没有 System 权限；真正的防线是工具白名单、只读和 scope，不是提示词。

第五层兜底。Router 仍会误判、模型也可能不听提示，所以靠评测和人工抽检发现问题。对外只说降低无依据回答，不说消除幻觉。

3可能被追问
  • 开关被 Router 误判绕过怎么办？→ 代码里二次判断，条件不满足一律强制取证。
  • 文档里藏"忽略前面指令"怎么防？→ 这些内容没有 System 权限，只当资料看；防线是白名单、只读、scope。
  • 为什么不下"消除幻觉"的结论？→ 模型是概率的，只能说降低无依据回答。
缺口

权限层要强调"检索内容是资料不是指令"，别让人觉得只靠 prompt 防注入。
