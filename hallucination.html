3完整回答

这题是两类问题。幻觉是模型给了没有证据支持的内容，读起来通顺，原文里没有；提示注入是输入里夹了指令，想覆盖系统规则。一个自己编，一个被诱导，注入还可能引到越权调用。

幻觉有三个来源：知识缺口、生成越界、语义误读。知识缺口靠策略和执行层治：Agent 有 allowGeneralKnowledge 开关，代码里还做第二道判断——开关打开、不是 Workflow、不是事故诊断、basis 是 GENERAL 或 MIXED 才允许通识，否则一律强制取证；没证据就说明没找到，或让用户补充。

生成越界靠引用层：模型只提交 Evidence ID 和段落，原文由程序从不可变原文回填，再校验引用存在、版本一致、区间对得上；校验不过就修复一次，再不过就降级。但这一层抓不住语义误读：原文写“只有管理员可导出”，回答成“所有人可导出”，引用是真的也可能是错的，目前只能靠评测和抽检。

提示注入的防线不在提示词，在权限：检索内容、附件、工具返回都当数据不当指令，它们没有 system 权限；工具只能走白名单，只读，受 scope 限制。真被诱导，能做的动作也有限。

最后是兜底：Router 会误判，模型也可能不听，靠评测和人工抽检发现。对外只说降低无依据回答，不说消除幻觉。

4可能被追问
  • 幻觉和提示注入什么区别？→ 幻觉是自己编，注入是输入里的指令劫持；注入能引起幻觉，也能引起越权动作。
  • 幻觉一般从哪来？→ 三类：知识缺口、生成越界、语义误读。
  • 引用校验能发现语义误读吗？→ 不能，它只校验引用存在、版本和区间一致，语义是否支持还要靠评测或人工。
  • 文档里藏“忽略前面指令”怎么办？→ 当数据不当指令，没有 system 权限；真防线是白名单、只读、scope。
  • 温度调到 0 能消掉幻觉吗？→ 不能，它只降低随机性，不解决知识缺口和误读。
  • 为什么不说消除幻觉？→ 模型是概率的，只能说降低无依据回答。
  • 开关被 Router 误判绕过怎么办？→ 代码里二次判断，条件不满足就强制取证。
缺口

语义误读拦不住；除了引用校验没做自动事实核对；注入只防了工具动作，没做内容脱敏。
