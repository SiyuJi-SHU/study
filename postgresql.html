PostgreSQL 建模、索引与事务

1一句话和流程
一句话

四块建模 → 索引按查询路径 → 三处事务 → 事实源

2完整回答

按四块建模。配置是 agents 加 agent_versions，主键 agent_id 加 version，版本不可变，改配置插新版本；知识是 datasets、documents、document_versions；运行是 agent_sessions、agent_runs、run_events；评测用量是 evaluation_sets、evaluation_jobs、model_calls。

索引按查询路径建：sessions 建 owner_id 加 agent_id，runs 建 session_id 加 created_at，run_events 用 run_id 加 sequence 做主键，document_versions 建 document_id。还有一个部分唯一索引保证同一 Session 只有一个活动 Run。

事务三处：创建 Run 并写第一条事件；切换知识库活动版本；完成 Run 并写结果和事件。要么全成功要么全回滚。用 JdbcTemplate 加显式事务，不把长事务包在模型调用外面。两个请求同时建 Run 时，先锁当前 Session 行再检查活动 Run，让并发排队；finish 用带状态条件的更新按影响行数判断，防止晚到结果覆盖已取消的 Run。

PostgreSQL 存事实和状态，Milvus 和 Lucene 只是可重建的派生索引。

3可能被追问
  • result_json 为什么用 TEXT 不用 JSONB？→ 现在不做字段级查询，需要时再换。
  • 事务为什么不包模型调用？→ 模型调用时间长，包进去会拖住连接和锁。
  • 版本不可变怎么实现？→ agents/agent_versions 主键 agent_id+version，更新就插新行。
缺口

主键、索引、事务三块各能举一个真实字段，"部分唯一索引保单一活动 Run"是亮点要主动说。
