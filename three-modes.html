1

三种行为模式怎么做

1一句话和流程
一句话

三种模式的差别只有一个——谁拥有“选工具”这个权力

2完整回答

我一共配了三种行为模式，按“谁拥有选工具的权”来分。

第一种是 ReAct。模型每一轮都能看到工具列表，自己决定调哪个、参数是什么，返回的是原生 tool_calls。Java 收到后只做四件事：按名字找工具、校验参数、去重、执行，然后把结果作为一条 tool 消息回填。同一轮可以并行调多个工具；相同参数再调一次不会执行，会返回 repeated_request；连续两轮没有新证据就停。适合开放性问题，路径不确定，需要边查边想。

第二种是 Plan。模型先输出一个计划，最多六步，每步有 id、目标、依赖。然后逐步执行：执行前模型只做一件事——为当前这一步选一个工具和参数，输出 action 等于 execute 的 JSON；Java 解析后执行，把结果记成一条 observation。执行完模型再判断这一步算不算完成：继续、结束、重规划或要求澄清。重规划最多两次，同一步最多三次尝试。适合步骤明确、需要先想清楚再动手的任务。要注意，它没有第二个 agent，执行的就是同一段 Java 循环。

第三种是 Workflow，这条是 Java 主导。先把告警和日志固定成一份现场快照；Supervisor 调一次模型，只输出一到三个调查方向，不碰工具；每个方向开一个线程，复制一份独立上下文，预算按方向均分；线程里 Java 按写死顺序取证，先查知识库，没文档再做全文检索，最多读两篇原文；证据齐了才调模型写分析，这次不带工具。最后合并各方向证据，分析作为候选，再统一生成一次答案。适合事故诊断这种流程固定的场景。

三种模式的共同点：都过同一个工具网关，都有总超时、调用次数上限和证据预算，结果都统一回填，不会出现某种模式绕过权限。

4我项目里的代码

① ReAct 的循环：模型返回 tool_calls，Java 逐个执行并回填：

var output=e.generate(true);
if(!output.hasToolCalls()) return ...;
for(var call:output.getToolCalls()){
    var tool=e.tools.stream().filter(t->t.name().equals(call.name())).findFirst();
    Object result=e.call(tool.get(),args,e.context);
    responses.add(new ToolResponseMessage.ToolResponse(call.id(),call.name(),e.encode(result)));
}

② Plan 的契约：模型只能输出这种 JSON，Java 按名字找工具：

{"action":"execute","tool":"tools.name中的名称","arguments":{}}

③ Workflow 的 Supervisor 和 Worker 取证：

// Supervisor：只出方向
String raw=e.models.call(e.models.create(.1,800,.9),"workflow-supervisor",
    "...只返回JSON：{\"directions\":[...]}", e.encode(...));
// Worker：Java 写死顺序，不经过模型
call.accept("knowledge.search", ...);
call.accept("documents.search", ...);
call.accept("documents.read", ...);
5可能被追问
  • ReAct 和 Plan 最大区别是什么？→ 谁承担“步骤”这个结构。ReAct 没有显式计划，边查边想；Plan 把步骤外化成数据，可观察、可重规划。
  • 为什么 Workflow 不让模型选工具？→ 取证路径固定，让模型选只增加不确定性；模型的价值在读懂证据和解释。
  • 三种模式会混用吗？→ 不会，按 Agent 版本固定一种，避免同一问题跑出不同行为。
  • ReAct 怎么防死循环？→ 轮次上限、重复请求检测、连续两轮无新证据就停，再加总超时。
  • Plan 什么时候重规划？→ 观察后发现目标没完成、原计划又走不通，最多两次。
缺口

三种模式没做同题 A/B 对比；Plan 的重规划成功率没统计；Workflow 方向数硬编码上限 3。
