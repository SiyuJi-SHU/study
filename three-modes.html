1

三种行为模式怎么做

1一句话和流程
一句话

三种模式都是单 Agent；ReAct 是标准 tool loop，Plan 是单模型三阶段 + Java executor，Workflow 是固定并行取证，不是多 Agent。

2完整回答

我项目里配了三种行为模式，按任务的开放程度选。

第一种是 ReAct，就是单模型加工具循环。模型每一轮根据工具 schema 输出 tool_call，Java 校验参数、执行工具，把结果回填给同一个模型，它再决定继续查还是提交答案。我加了轮次上限、重复请求检测，连续两轮没有新进展就停。它和 LangChain 的 ReAct agent 基本是同一套。

第二种是 Plan–Execute–Replan，还是同一个模型，但先把步骤外化成计划，最多六步，每步有目标和依赖。执行时模型只为当前这一步选工具和参数，Java 执行；执行完模型判断这一步算不算完成，继续、重规划还是结束。重规划最多两次，单步最多三次。它更像 Plan-and-Execute 的简化版：主流一般把 executor 做成一个 agent，我把 executor 收敛成 Java 工具网关，少一层循环。

第三种是 Workflow，后端主导的固定流程。先把告警和日志固化成现场快照，Supervisor 模型只调一次，给出最多三个调查方向；每个方向开一个 Java 线程，按写死顺序取证：先查知识库，没有再全文检索，最多读两篇原文；取证完每个线程让模型写一段分析；最后合并证据，统一一次模型生成答案。这里 Worker 是线程，不是独立 Agent，它不选工具，也不会再派活。

所以三种都是单 Agent，差别在控制流：ReAct 是模型自己边查边想，Plan 是模型先计划再逐步执行，Workflow 是后端定流程、模型只在开头定方向和最后汇总。

三种模式都过同一个工具网关，都有超时、调用次数和证据预算，不会绕过权限。

3主流对照
模式主流框架我的实现
ReAct单 LLM + tool loop（LangChain / LangGraph ReAct agent）同一模型；Java 顺序执行；加预算/去重/停止条件
Planplanner + executor agent + replanner（LangChain PlanAndExecute / LangGraph plan-and-execute）同一 LLM 三阶段；executor 收敛成 Java 工具网关
Workflowsupervisor + worker agents（LangGraph supervisor / CrewAI hierarchical）Supervisor LLM + Java 线程固定取证；不是多 Agent
4我项目里的代码

① ReAct 的循环：模型返回 tool_calls，Java 逐个执行并回填：

var output=e.generate(true);
if(!output.hasToolCalls()) return ...;
for(var call:output.getToolCalls()){
    var tool=e.tools.stream().filter(t->t.name().equals(call.name())).findFirst();
    Object result=e.call(tool.get(),args,e.context);
    responses.add(new ToolResponseMessage.ToolResponse(call.id(),call.name(),e.encode(result)));
}

② Plan 的契约：模型只能输出这种 JSON，Java 按名字找工具：

{"action":"execute","tool":"tools.name中的名称","arguments":{}}

③ Workflow 的 Supervisor 和 Worker 取证：

// Supervisor：只出方向
String raw=e.models.call(e.models.create(.1,800,.9),"workflow-supervisor",
    "...只返回JSON：{\"directions\":[...]}", e.encode(...));
// Worker：Java 写死取证顺序；取证完再调一次模型写分析
call.accept("knowledge.search", ...);
call.accept("documents.search", ...);
call.accept("documents.read", ...);
5可能被追问
  • ReAct 和 Plan 最大区别是什么？→ 谁承担“步骤”这个结构。ReAct 没有显式计划，边查边想；Plan 把步骤外化成数据，可观察、可重规划。
  • Plan 为什么不是 planner + executor agent + replanner？→ 我把 executor 收敛成 Java 工具网关，少一层 agent 循环；代价是执行阶段不能自主多步探索。
  • Workflow 为什么不是 LangGraph supervisor 多 Agent？→ 取证路径固定，Worker 不需要自主决策；多 Agent 会增加状态、权限、通信和调试成本。
  • ReAct 同一轮会并行调工具吗？→ 不会；流式 parallelToolCalls=false，Java 也是 for 循环顺序执行。
  • 三种模式会混用吗？→ 不会，按 Agent 版本固定一种。
  • ReAct 怎么防死循环？→ 轮次上限、重复请求检测、连续两轮无进展、总超时。
  • Plan 什么时候重规划？→ 观察后发现目标没完成、原计划又走不通，最多两次。
缺口

三种模式没做同题 A/B 对比；Plan 的重规划成功率没统计；Workflow 方向数硬编码上限 3。

边界

没有 A2A/独立 Agent 通信；Workflow 是固定取证流程，不是多 Agent。A2A 是跨 Agent/跨组织才需要的协议，不在当前场景的代价里。
