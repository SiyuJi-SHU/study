RAG 变动数据怎么处理

1一句话和流程
一句话

语义进索引，变动走事实源；metadata 里的业务主键是关键

阶段什么时候做什么
① 确认对象意图识别拿到商品 ID避免盲目检索
② 取语义向量库拿商品描述稳定知识
③ 取实时用商品 ID 查 Redis 或库价格库存会变
④ 组装拼成上下文模型拿到完整信息
补充

向量库一般存四样：切片 ID、向量、原文、metadata。metadata 里必须有业务主键，比如商品 ID，否则查不到实时字段。

静态信息进索引，变动字段不进索引。

2完整回答

电商商品问答里，商品描述基本不变，价格和库存天天变。如果都塞进向量库，每次调价都要重切、重嵌入、重建索引，旧引用还会失效。

做法是冷热分离。向量库只存稳定的语义内容，metadata 带上商品 ID；价格库存走 Redis 或数据库，用商品 ID 直接查。

流程四步：先确认用户问的是哪个商品，靠意图识别，也可以靠当前页面停留；再检索商品描述；然后用商品 ID 查价格和库存；最后组装成上下文交给模型。

为什么用 Redis：电商高并发，价格库存是热数据，提前预热到缓存，读延迟低。没有 Redis 直接查库也能做，只是并发上来扛不住。

我项目里没有价格库存，但结构一样：向量库只是可重建的索引，事实在 PostgreSQL；文档按版本存，原文不变。

**样例**

```text

向量库：chunk_id / vector / text / metadata{productId, documentId, version}

实时库：productId -> price, stock

```

3可能被追问
  • 价格能写进 chunk 吗？→ 不能。调价要重切重嵌入，旧引用还会失效。
  • metadata 里必须有什么？→ 业务主键，比如 productId、documentId、version，用来回查和过滤。
  • 没有 Redis 怎么办？→ 直接查 PG，加一层缓存也行；关键是别把变动字段写进索引。
  • 怎么知道用户问的是哪个商品？→ 意图识别，或者当前页面上下文。
缺口

项目里没有价格库存这类实时字段，也没有接 Redis。
