总管问 · 你被问过很多次的

你自己做的，和 WorkBuddy 这些主流的有什么区别？做这个的意义何在？

讲稿区别和意义

先说区别。WorkBuddy 这些是成熟的产品，通用的能力和稳定性肯定比我自己做的好，这点我不比。我做的也不是一个要替代它们的产品。

我做它是为了三件在现成产品里我自己做不到的事。

一是链路是我自己的。Agent 怎么跑、工具怎么调、上下文怎么管，我都能改。核心是一个 AgentRuntime，一次运行的整个生命周期都归它管：先固定这次用哪个 Agent 版本、哪些资料、哪些工具；再设好预算，比如总超时、最多调几次工具；然后做意图路由，按版本里定的模式去执行，这三种模式我做了 ReAct、计划执行和固定流程；工具真正执行前都过一遍 Java 的校验；最后校验答案和引用，落库，往前端推事件。另外每个 Agent 的配置是一个不可变的版本，一个会话固定用其中一个版本，所以后来改了配置，也不影响历史对话，回头能复现。

二是能追溯。每一次运行，从头到尾的东西都落在 PostgreSQL 里：最终状态、答案、证据、执行计划、模型用量，还有按序号排的事件，前端断了可以按序号补发。回答里的每句引用带一个证据 ID，模型只给 ID，原文由程序按 ID 回填进去。所以答错了，我能查到是哪一次运行、用的哪个版本、检索到了什么。评测的时候我也按这个分三种情况：候选里压根没召回、召回了但重排丢了、还是资料本身就没有。

三是按自己的需要配 Agent，比如读书和论文的、运维问答的。

再说意义，有两层。对我自己，是把 Harness 这一层真正做懂了，不是只会配置。对工作，如果团队要做定制的 Agent，我能改到里面去，而不只是在现成平台上配一配。
