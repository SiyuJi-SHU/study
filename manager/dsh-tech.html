先认词 · 扫一遍，不用背

学过它的人都会的基础词

dshDeepSeek Harness 的简称。它的命令就叫这个，比如 dsh web。
Harness包在模型外面的那层程序。模型只会「进一段文字、出一段文字」，读文件、跑命令、记历史这些事都是 Harness 替它干的。
Agent模型加上工具加上循环，能自己动手干活。你的 Totoro 里每个 Agent 就是这个。
agent loop转圈：调模型 → 模型说要调工具 → 替它调 → 结果喂回去 → 再调模型。直到模型不再要工具为止。
工具 Tool模型能调的一个函数。读文件、搜知识库、发飞书消息，都是工具。你写的 knowledge.search 就是一个。
插件 Plugindsh 里「加一块东西」的单位。工具、提示词、检查、模型适配、界面页面，都是插件。
ctx插件的公共容器。插件把自己提供的服务挂上去，比如 ctx.tools、ctx.llm，别的插件按键来拿。
Cordisdsh 底下的插件框架，管插件的加载、卸载、热重载。
连接器接一个外部服务的插件，比如飞书、钉钉。你授权后，它给模型一组工具，替模型去调外部接口。
MCP一个通用协议，规定 Agent 怎么发现和调用外部工具。别人写好的 MCP 服务能直接接。dsh 里接 MCP 的东西本身也是插件。
子 Agent / 团队把一部分活派给另一个 Agent；多个 Agent 共用一块任务板分工。
会话日志只往后加、不改动的事件记录。模型看到的历史是从它推出来的，所以能回放、能恢复。
审批 / 沙箱Agent 动你电脑前的两道关。审批是弹窗问你；沙箱是限制它能启动什么、能碰什么。
Profile / PatchProfile 是一套起了名字的组装方案；Patch 是一份配置文件，按它改掉或插入某一块。
技能 Skill一包现成的做法，比如处理 Word、PPT、Excel 的 /office。类似你给 Agent 写的任务说明。
产品形态 · 认真看

它是什么、能干什么

  • 一句话：它是 DeepSeek 开源的 AI 干活助手，跟你现在用的 TRAE、还有 Claude Code、WorkBuddy 是同一类产品。装在本机，有界面，你跟它对话，它替你动手。
  • 现在的阶段：官方叫「开发者预览」，版本号带 alpha，还在快速迭代，以后会有不兼容的改动。
  • 怎么用：一条命令 npx @deepseek-ai/dsh web 就在本机起一个网页版；也有桌面版；还有给程序调的 SDK 和跑一次就退出的模式。
它能干什么（都是最近版本更新日志里写的）
读写文件、跑命令在你电脑的工作目录里干活，改代码、跑脚本。
审代码接 GitHub 的 PR 和 GitLab，在页面里看改动，跟它一起审。
派子 Agent、开团队把一部分活派给子 Agent；也能多个 Agent 共用一块任务板分工。
连外部服务飞书、钉钉、企业微信、腾讯文档、Notion、Linear 都有连接器，在对话里直接用。也支持 MCP。
处理文档Word、PPT、Excel，内置了 /office 技能。
定时任务比如每周回顾这种自动化任务。
插件市场装别人的插件；也能把自己私有的 Git 仓库加进来当插件来源。
多开会话会话能分叉、能共享给别人、有已读未读。

和「个人定制 Agent」什么关系：二面说团队在用它做定制 Agent 和交付。在上面做定制，就是写自己的插件、装自己要的工具、接自己公司的服务，把它改成贴合自己工作的样子。不用从零写一个，这也是它和你 Totoro 最大的不同：你是从零造了一个，它是给你一个现成的让你改。

只学三点技术

记这三个词就够

1 一切皆插件模型、工具、会话记录、权限审批，连 agent loop 本身都是插件。想换哪块就挂一个插件，不改循环。这是它和别家最大的不同。
2 执行前把关Agent 要动你电脑之前有一道关：权限、审批、沙箱。可以设成「要问我」，不同意就不放行。
3 会话日志模型看到的所有东西都记在日志里，只往后加不改。所以能回放、能恢复、能从一个点分叉出新会话。

对应 Totoro：你的 AgentRuntime 是一个类把这三件事都管了。dsh 是把每一块拆成插件，还在每个节点上开了事件口，谁都能挂监听器。你写的「工具执行前的 Java 校验」，对应的就是第 2 点。

最后背 · 被问到时说

DeepSeek Harness 是 DeepSeek 开源的 Agent Harness，现在还是开发者预览阶段。说白了它跟 Claude Code、WorkBuddy 是一类产品：装在本机，有网页版和桌面版，能让模型读写文件、跑命令、改代码、审 PR，还能接飞书、钉钉这些外部服务。

它最大的特点是所有东西都是插件，连 agent loop 本身也是。想换哪块就挂一个插件，不用改循环。这和我在 Totoro 里做的 AgentRuntime 是一个路数，区别是 Totoro 是我从零写的，它是把每一块都做成了谁都能挂的扩展点。团队在用它做定制 Agent，我觉得就是这个意思。

有余力再看

Harness 就是包在模型外面的那层程序

  • 模型本身只会一件事：给它一段文字，它吐出一段文字。它不会读文件、不会跑命令、也记不住上一轮说了什么。
  • 中间这层要有人干：把用户的话和历史整理好给模型，告诉它有哪些工具能调，它说「我要调某个工具」时替它真去调，再把结果喂回去让它接着想，整个过程还要记下来。这层就叫 Harness。
  • 你在 Totoro 里写的 AgentRuntime 干的就是这件事。
  • DeepSeek Harness（简称 dsh）是 DeepSeek 把自家这一层开源出来的。TypeScript 写的，MIT 协议，现在版本 0.2.3-alpha.2，还在 alpha。
  • 它最大的特点：这一层的每一块都是插件。模型适配器、工具、会话日志、权限审批，连 agent loop 本身也是插件。没有一个要你去改源码的「内核」。
第 1 课 · 底层框架

Cordis：一个插件框架

dsh 是长在 Cordis 上的。Cordis 管的事只有一件：让一堆插件能挂上去、能互相找到、能被干净地卸掉。五个概念：

插件一个函数，被加载时调用，拿到一个 ctx，然后往里登记东西。也可以写成一个 Service 类。
ctx服务的容器。一个服务占一个固定的键：ctx.tools、ctx.llm、ctx.sessions。别的插件按键拿，不去 import 具体实现。
inject插件声明自己要用哪些服务。声明了，就等这些服务就绪才启动。加载顺序靠这个表达，不用手写先启动谁。
事件服务声明事件名，别人挂监听器。分发方式有五种：emit（只通知）、waterfall（一串依次处理）、parallel（并行）、serial（按序）、bail（碰到第一个返回值就停）。
可撤销插件登记的每样东西都带一个撤销动作，插件卸载时自动撤。用 ctx.on()、ctx.plugin() 登记的自动算；定时器、连接这种框架不认识的，要包在 ctx.effect() 里。
瀑布事件（waterfall）单独说一句
  • 监听器拿到的参数最后多一个 next。调了 next()，才轮到下一个监听器；不调，就到此为止。
  • 所以想拦截某个动作，不用改循环，挂一个监听器、不调 next 就行。

对应 Totoro：你写的是 Spring。插件像 @Component，ctx 像容器，inject 像 @Autowired，事件像 Spring 的 ApplicationEvent，只是多了「不调 next 就拦住」这种玩法。区别是 Spring 里业务类之间还是直接互相调用，dsh 里插件之间只通过 ctx 上的服务和事件说话。

第 2 课 · 怎么组装

Profile、Bundle、Patch：一套是配置叠出来的

Profile一套起了名字的组装方案。自带的几种：web（带网页界面）、headless（跑一次任务就退出）、sdk（给程序调）、acp（自动化用）。
Bundle 组合包一批插件加它们的配置，打包在一起。dsh-base 是公共底座：模型适配器、工具、持久化、沙箱与审批、设置、凭据。
Patch 补丁一份配置文件，按 id 找到某个插件条目，改它的配置，或者插一个新条目进去。
HMR 热重载改了配置文件，程序不重启，自动把相关插件卸掉再装回去。
叠的顺序

profile 里列的组合包 → profile 自己的 cordis.patch.yml → home patch → 命令行 --patch。后面的盖住前面的。所以官方的东西你一行不用改，写个 patch 就能换掉任何一块。

对应 Totoro：Totoro 的装配是写在代码里的，构造函数里注入一堆 Service，要换实现就得改代码重新编译。dsh 是配置文件叠出来的，改一个 patch 文件就是另一套。

第 3 课 · 基本逻辑

转一圈发生了什么

  • 步骤：调一次模型，加上这次回复引发的工具调用。
  • 轮次：从拿到你一句话开始，到模型和工具都停手为止。一个轮次里有零个或多个步骤。
一个轮次里的顺序
  1. turn/start。领走用户这句话。
  2. 组装。定好这次用哪个模型，拼提示词，定这次模型能看到的工具。
  3. agent/pre-step。瀑布事件。监听器可以放行、改写要送进去的消息，或者直接拒绝。
  4. step/start，调模型。系统的更新和用户消息先记进日志，再从日志推出这次请求的历史，然后流式调模型。
  5. assistant/message。模型的回复记进日志。
  6. 模型要调工具。记 tool/call，然后走三道：执行前（钩子、权限、沙箱）→ 守卫（只能拒绝或不表态）→ 执行（超时、重试）→ 执行后（接受、拦截、替换结果），最后记 tool/result。
  7. step/end。工具结果还要喂给模型，或者用户又发了话，回到第 3 步再来一个步骤。
  8. turn/end。没有要干的活了，轮次关掉。
事件分三类
会话事件记进日志的事实，重新加载以后还在。turn/*、step/*、各种 message、tool/* 都是。
agent/*正在进行的协调：收件箱、步骤、状态、请求。用来观察或拦截进行中的工作。
能力事件给某项能力挂策略，不用动循环。fs/*、tools/*、telemetry/*。

对应 Totoro：AgentRuntime 的 execute 方法，从 TaskRouter 判断意图，到拼 messages，到 ReActExecutor 跑，到校验、落库，是一条写死的流程。dsh 把这条流程的每个节点都发成事件，谁都能在节点上挂东西。你写的「工具执行前的 Java 校验」，对应的就是执行前那一道。

第 4 课 · 记忆从哪来

会话日志：模型看到的历史是推出来的

  • 日志只往后追加，不改以前的内容。
  • 模型每轮看到的历史，不是另外存的一份，而是从日志里推出来的。
  • 原则一句话：模型可见即已记录。模型看到过的每样东西，都必须能从日志重建。
  • 所以回放、恢复、从一个点分叉出新会话，都是从日志来的。
  • 对话太长时有压缩：先把工具结果剪短，还不行就把前面的内容做成摘要。

对应 Totoro：你落的是 agent_runs 和 run_events，下一轮从上几次运行的 result 里拼回历史。思路一样，dsh 更彻底，连每一次请求的完整上下文都能重建。上下文压缩你没做，是靠只取最近 4 轮加截断。

第 5 课 · 怎么定制

能力接缝：换一个提供方，行为就变了

  • 一项可以整体替换的能力，固定分三个角色：接口、提供方、使用方。
  • 例子：shell 的接口，本机的 Bash 提供方，给模型用的 Bash 工具。
  • 把提供方换成远程沙箱，Bash、终端、LSP 就一起搬到沙箱里跑了，工具本身一行没动。
  • 「个人定制 Agent」在 dsh 里就是这么做的：不改循环，换插件。

查词表 · 不用背
底层框架
CordisDeepSeek Harness 底下的插件框架。插件往一个共享的上下文 ctx 里登记服务、事件和清理动作，框架负责加载、卸载和热重载。
Effect 副作用插件登记的每样东西都带一个撤销动作。用 ctx.on()、ctx.plugin() 登记的自动算；定时器、连接这类框架不认识的资源，要包在 ctx.effect() 里。
Service 服务插件对外提供的能力，挂在 ctx 的一个键上，比如 ctx.tools、ctx.llm、ctx.sessions。别的插件通过这个键来用。
Preset 预设一个 agent 的能力组合：装哪些工具、哪段提示词。换个预设就是换一种 agent。
怎么运行
Agent Loop不断重复「调模型 → 执行工具 → 结果回填」，直到没有工具要调。默认实现在 core/agent-loop 包里，它自己也是个插件。
审批 Approval工具执行前弹一次窗问用户，同意才放行。没人回答就当拒绝。
守卫 Guard只能「拒绝」或「不表态」的检查，不能改写调用。
沙箱 Sandbox限制工具能启动什么进程、能碰什么。把文件系统和进程的提供方指向远程沙箱，Bash、终端这些工具就一起搬到沙箱里跑了。
Scope 作用域按 agent 划分的登记范围。一个工具或提示词片段要么全局可见，要么只属于一个 agent；同一个名字，局部的盖住全局的。
怎么扩展
Seam 能力接缝一项可以整体替换的能力，固定分三个角色：接口定义、提供方、使用方。
LLM 适配器把某家模型的接口接进来的插件，登记在 ctx.llm 上。换模型就是换这个插件。
Hook 钩子挂在事件上的监听器，在不改循环的前提下加检查或处理。
Subagent把一部分活委派给另一个 agent 去做。它的提供方也能换：可以新起一个子 agent，也可以把一轮交给别的产品。
Agent Teams多个 agent 共用一块任务板来分工。
Jobs后台跑的任务，模型可以用工具查看或停止。
MCP接外部工具的协议，仓库里有专门的 mcp 包。
工程
TypeScript + ESM整个仓库用 TypeScript 写，模块全部是 ESM，编译开严格模式。
pnpm 工作区整个仓库是一个 pnpm monorepo，按目录分组：core、llm、shell、sandbox、compaction、subagent 等几十个包。
SDK给程序调用的接口，TypeScript 版走 JSON-RPC，另有 Python 版。
Electron桌面应用，用 Electron 做，和命令行版共用产品数据。
